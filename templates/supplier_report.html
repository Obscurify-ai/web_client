Supplier report

Obscurify.ai doesn't store your prompts. The companies that run the models still see them, and their promises about deleting prompts are only as good as their systems. So every week we send a batch of them prompts that carry traps, starting with the ones tested longest ago.

How the test works

A canary is a secret that exists in exactly one place. If anyone ever uses it, you know where it came from.

  1. One prompt, one host. Each prompt looks like an ordinary coding question, the kind people paste their config into. It holds web addresses, a git repository, a login and an AWS access key, all made for that single prompt. We send it to one host, pinned so that no other host may serve it. Where the supplier says which host answered, we check that it was that one. We record which model it was for and which privacy settings were on.
  2. Every host, in turn. We work through every company that runs the models you can pick on Obscurify.ai, a batch each week, starting with the ones tested longest ago. We also send separate prompts for each major model family (DeepSeek, GLM, Kimi, Qwen and others) to every host that runs it. Published research found prompts flowing from a third-party host back to the lab that made the model, so the host alone isn't enough to test.
  3. We watch the traps. The addresses lead to servers on a domain that has nothing to do with us. Each AWS key is a Thinkst Canarytoken that reports any use. If someone opens a link, tries to clone the repository, tries the login, or tests the key, we see when, from what network and with what software.
  4. We sort what we see. A secret used after the request finished means someone read the prompt later: a breach, a log someone reads, or data passed on to another company. A link opened while the request was still running is listed separately, because some systems fetch links as part of answering.

We test ourselves too

The same traps go into requests that our own service turns away before any supplier sees them (an unknown model, an account with no balance), and into secrets planted on our own servers. If one of those fires, the leak is ours, and this page will say so.

Other weekly checks

  • Hidden instructions. Every uncensored model is sent "Hello." and we compare the input tokens we're billed for. A jump means a supplier has slipped its own system prompt in front of yours. We caught one doing it in November 2026 and moved those models to a different supplier.
  • Refusals. Uncensored models get three requests mainstream models refuse. A model that starts refusing has been swapped for something else.

Limits

  • A clean result means nobody has acted on a canary yet. It can't prove that nobody kept a prompt.
  • Careful attackers can spot some public canary keys and leave them alone. Our other traps don't look like canaries.
  • Each host is tested in turn, not every week, so a host that leaks only for a short time can be missed.
  • We test the companies that answer a model normally. When one is down and a request moves to a backup, that backup may not have been tested yet.

If you send secrets to any AI model, assume the host can read them. You can turn on secret scrubbing for an API key, which replaces common key formats with placeholders before the prompt leaves our servers.

The method comes from Dragos's research, Three breaches, endless leaks: Your AI supply chain needs canaries (November 2026). They sent about two million seeded prompts and found three breached providers, resellers reading prompts, and zero-retention settings ignored. Updated weekly. See also our privacy policy.
